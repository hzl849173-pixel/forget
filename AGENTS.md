# Workout Journal - AI Agent Instructions

## Project Overview

Workout Journal is a premium, minimalist workout logging application.

Its purpose is NOT to generate workouts.

Its purpose is to help users log completed workouts as quickly and effortlessly as possible.

The primary goal is:

"A user should be able to record an entire workout in under 30 seconds."

Every design and engineering decision should support this goal.

---

## Core Philosophy

Prioritize simplicity over features.

Remove unnecessary taps.

Remove unnecessary screens.

Remove unnecessary animations.

Never sacrifice usability for visual effects.

The app should feel calm, premium and effortless.

---

## Target Users

People who already know their workouts.

Gym beginners.

Intermediate lifters.

Advanced lifters.

Users currently logging workouts in Notes, Notion or paper.

---

## Core Features

Google Sign-In.

Workout history.

Exercise library.

Favourite exercises.

Custom exercises.

Search exercises.

Multiple muscle groups in one workout.

Weight entry.

Sets.

Repetitions.

Auto workout title suggestion.

Last 30 days workout history.

Show previous week's corresponding workout.

Offline-first experience whenever practical.

---

## Things This App Is NOT

Not a workout generator.

Not a social media app.

Not a calorie tracker.

Not a bodybuilding encyclopedia.

Not a fitness coach.

Avoid unnecessary features.

---

## UI Principles

Minimal.

Premium.

Modern.

Fast.

Consistent.

No clutter.

Prefer whitespace.

Use subtle animations.

Avoid unnecessary colors.

Avoid heavy shadows.

Keep navigation obvious.

---

## UX Principles

Every interaction should minimize taps.

The user should never feel lost.

Searching should be extremely fast.

Frequently used actions should require minimal effort.

The workout logging flow should be optimized above everything else.

---

## Technical Principles

Use Expo.

Use React Native.

Use TypeScript.

Write reusable components.

Avoid duplicated code.

Prefer composition over large components.

Prefer maintainability over clever code.

---

## Code Quality

Keep files reasonably small.

Use meaningful names.

Avoid magic numbers.

Avoid unnecessary comments.

Prefer readable code.

---

## Before Writing Code

Always understand existing code first.

Reuse existing components.

Follow existing design language.

Never introduce inconsistent UI.

Ask before installing new dependencies.

Explain major architectural decisions.

---

## Success Criteria

The app should feel like a polished product rather than a student project.

Users should immediately understand how to use it.

Logging a workout should be extremely quick.

The experience should be enjoyable enough that users prefer it over the Notes app.
